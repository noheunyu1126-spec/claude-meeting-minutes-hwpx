사용자 입력: $ARGUMENTS

행정기관·대학 「회의록」 양식대로 HWPX 회의록을 만든다.
**`meeting-minutes-hwpx` 스킬을 먼저 로드**하고 그 SKILL.md 와
`references/writing-guide.md` 의 규칙을 따른다.

## 입력 해석

위 입력에서 **회의 제목**과 **자료 위치**를 뽑는다.

- 입력이 비어 있으면: 현재 폴더와 하위 폴더에서 아직 회의록이 없는 회의 자료
  폴더를 찾아 후보를 보여주고, `AskUserQuestion` 으로 어느 회의인지 고르게 한다.
- 제목만 있고 자료가 없으면: 제목과 비슷한 이름의 폴더·파일을 찾아본다.
  그래도 없으면 자료를 어디서 가져올지 한 번 묻는다.
- 자료 경로가 폴더면 그 안의 PDF·HWP·PPT·TXT 를 전부 훑는다.
- 이미 만든 개요 `.txt` 를 주면 내용 작성 단계를 건너뛰고 바로 빌드한다.
- 입력이 회의록 요청이 아니면(설정 변경·질문 등) 빌드하지 않고 그 요청에 답한다.

## 진행

1. **PDF 자료는 먼저 추출기를 돌린다.** 텍스트와 그림 후보가 한 번에 나온다.
   ```bash
   python <스킬>/scripts/extract_figures.py "자료.pdf" -o ./_추출
   ```
   `_추출/text.md` 를 읽어 내용을 파악한다. 텍스트가 거의 없으면 스캔본이므로
   `_추출/pages/pNN.png` 를 Read 해서 이미지로 읽는다.
   HWPX 는 `Contents/section0.xml`, HWP 는 한글 COM 으로 변환해 읽는다.
2. **그림을 직접 골라 넣는다.** 사용자가 따로 고르라고 하지 않아도 알아서 고른다.
   - `text.md` 의 쪽 제목으로 후보 성격을 판단하고, 쓸 만한 것은 **Read 로 눈으로 확인**한다.
   - 본문에서 언급한 내용을 보여 주는 개념도·화면 캡처·비교 그래픽만 2~6장.
     목차·간지·로고는 버리고, 행·열이 뚜렷한 표 그래픽은 `[표]` 로 옮기는 편이 낫다.
   - 캡션은 쪽 제목을 다듬은 짧은 명사구(`[메인 화면]`).
   - 넣은 그림은 본문에서 그 내용을 설명하는 `◦` 바로 뒤에 둔다.
   - 발표자료 자체가 빈 프레임이면 그림 없이 쓰고 본문에 "별도 확인 필요"로 남긴다.
     **없는 그림을 지어내지 않는다.**
3. 같은 폴더의 `참석자명단.*`, `… 개최.pdf`(개최 공문)에서 일시·장소·참석자를 찾는다.
4. 그래도 비는 칸만 모아 `AskUserQuestion` 으로 **한 번에** 확인한다.
   `defaults.json`(작성자·관리자·장소·상시 참석자)이 채워주는 칸은 묻지 않는다.
   회의 일시는 추측하지 않는다 — 자료에 없으면 반드시 묻는다.
5. 개요 텍스트(`개요.txt`)를 작성한다 — 완성된 회의록 모양 그대로 쓴다.
   서식은 `python <스킬>/scripts/build_minutes.py --template` 로 확인.
6. 빌드한다. 출력 파일은 **자료가 있던 폴더**에 만든다.
   ```bash
   python <스킬>/scripts/build_minutes.py 개요.txt --images-dir ./_추출 --pdf
   ```
   파일명은 자동으로 `<회의명>_회의록_<YYYYMMDD>_<작성자>.hwpx`.
7. 만들어진 PDF 를 페이지별로 렌더해 **직접 눈으로 확인**한다. 표가 잘리거나 그림이
   비어 보이거나 4쪽을 넘으면 개요를 고쳐 다시 빌드한다.

## 보고

작업이 끝나면 이렇게만 알려준다.

- 만들어진 파일 경로(클릭 가능한 링크)와 쪽수
- 절 구성 한 줄 요약
- **자료에서 확인되지 않아 비워둔 칸**(있으면)
- 개요 파일 경로 — 내용을 고치고 싶을 때 이 파일만 수정해 다시 빌드하면 된다고 안내

회의록 파일을 열어서 보여달라는 뜻이 명확하면 `--open` 을 붙여 한글로 띄운다.
그렇지 않으면 열지 않는다.
