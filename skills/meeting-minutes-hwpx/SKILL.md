# meeting-minutes-hwpx





회의 **제목**과 **자료**(텍스트 / PDF / HWP / 발표자료 / 메모 무엇이든)를 받아


행정문서 체계를 갖춘 회의록을 HWPX 로 만든다.





## 결과물 서식 (양식.hwpx 그대로)





| 구성 | 서식 |


|---|---|


| 표제 | 연회색 박스 안 `회의록` (HY헤드라인M 20pt, 가운데) |


| 제목표 | `제 목`(4열 병합) / `일 시`·`작성자` / `장 소`·`관리자` / `참석자`(4열 병합), 라벨 셀 #F2F2F2 배분정렬 |


| 본문 머리 | ` ■ 회의 내용` (맑은 고딕 12pt) |


| 절 표제 | `1. 회의 목적` — 휴먼명조 14pt 굵게 |


| 소제목 | `가. 운영 현황` — 휴먼명조 13pt 굵게 |


| 글머리 1 | `◦ (라벨) 본문` — 휴먼명조 12pt, `(라벨)`만 굵게, 내어쓰기 |


| 글머리 2 | `- 본문` / 글머리 3 `○ 본문` |


| 단서 | `※ 본문` — 휴먼명조 10pt |


| 표 | 연청(#DAE3F3) 머리행 맑은 고딕 10pt 굵게 + 본문셀 10pt, 세로 병합·합계행 음영 지원 |


| 그림 | 테두리 없는 표에 1~N장 나란히 + `[캡션]` 행 |


| 쪽 | A4 세로, 1쪽 제외 하단 가운데 쪽번호, 본문 셀이 여러 쪽으로 자동 분리 |





## 작업 순서





1. **자료 읽기 + 그림 추출** — 발표자료·보고서 PDF 는 `scripts/extract_figures.py` 한 번으로


   본문 텍스트와 그림 후보를 같이 뽑는다. **PDF 를 받으면 이걸 먼저 돌린다.**


   ```bash


   python scripts/extract_figures.py "자료.pdf" -o ./_추출


   ```


   - `_추출/text.md` — 쪽별 제목·본문·그림 후보 목록. **이것을 읽고 내용을 파악한다.**


   - `_추출/fig_pNN_k.png` — 잘라낸 그림. 회의록에 넣을 때 이 파일명을 `[그림]` 에 쓴다.


   - `_추출/figures.json` — 쪽·크기·`ink`(내용 밀도)·주변 문구


   - `_추출/pages/pNN.png` — 쪽 전체 렌더. 그림을 고르기 전에 맥락을 볼 때만 Read 한다.





   그 외 형식: 텍스트는 그대로, HWPX 는 `Contents/section0.xml`, HWP 는 한글 COM 으로 변환.


   텍스트가 거의 없으면 스캔본이므로 쪽을 PNG 로 렌더해 이미지로 읽는다.


   ```bash


   python -c "import fitz,sys;d=fitz.open(sys.argv[1]);[p.get_pixmap(dpi=140).save(f'pg{i+1}.png') for i,p in enumerate(d)]" 자료.pdf


   ```





2. **그림 고르기** — 후보를 전부 넣지 않는다. `text.md` 의 쪽 제목으로 후보 성격을 판단하고,


   본문에서 언급한 내용을 **보여 주는** 것만 2~6장 고른다.


   - 고를 때 `pages/pNN.png` 또는 후보 PNG 를 실제로 Read 해서 눈으로 확인한다.


   - 개념도·화면 캡처·비교표 그래픽은 좋고, 목차·간지·로고·아이콘 나열은 버린다.


   - `ink` 가 0.05 미만이면 내용이 희박한 크롭이니 특히 의심한다(빈 박스는 이미 걸러져 있다).


   - 표로 옮길 수 있는 내용(행·열이 뚜렷한 표 그래픽)은 **그림보다 `[표]` 가 낫다.**


   - 캡션은 쪽 제목을 다듬어 `[메인 화면]` 처럼 짧은 명사구로 쓴다.


   - 한 줄에 1~2장. 가로로 긴 그림은 혼자, 비슷한 비율 두 장은 나란히 둔다.





3. **빠진 항목 확인** — 일시·장소·작성자·관리자·참석자는 자료에 없으면 **한 번에 모아서** 사용자에게 묻는다.


   같은 폴더의 `참석자명단.hwp`, 개최 공문(`간담회 개최.pdf`) 에 들어 있는 경우가 많으니 먼저 찾아본다.


4. **본문 설계** — `references/writing-guide.md` 의 절 구성·문체 규칙을 따른다.


5. **개요 텍스트 작성** → `python scripts/build_minutes.py 개요.txt --images-dir ./_추출 --pdf`


   (표·그림이 복잡하거나 프로그램으로 생성할 때는 콘텐츠 JSON `-c` 를 쓴다)


6. **검증** — 출력 JSON 의 `PASS: true` 와 `empty_fields` 확인. 이어서 만들어진 PDF 를


   페이지별 이미지로 렌더해 **직접 눈으로** 본다. 표 잘림·그림 넘침·4쪽 초과가 없어야 한다.


   ```bash


   python -c "import fitz,sys;d=fitz.open(sys.argv[1]);[p.get_pixmap(dpi=120).save(f'pg{i+1}.png') for i,p in enumerate(d)]" 결과.pdf


   ```


7. 개요 파일과 쓴 그림은 결과물 옆에 남겨 둔다(`--images-dir` 로 쓴 그림은 `그림/` 폴더에


   복사된다). 내용을 고칠 때 개요만 수정해 다시 빌드하면 된다.





## 빌드 스크립트





입력은 **텍스트 개요**(권장, 사람이 읽고 고칠 수 있다)와 **콘텐츠 JSON** 둘 다 받는다.





```bash


python scripts/build_minutes.py --template                 # 개요 작성 서식 출력


python scripts/build_minutes.py 개요.txt --pdf --open      # 개요 -> hwpx(+pdf, 한글로 열기)


python scripts/build_minutes.py -c 내용.json -o 결과.hwpx   # JSON 으로 생성


python scripts/build_minutes.py --schema                   # 콘텐츠 JSON 스키마


python scripts/build_minutes.py --selftest -o 확인.hwpx     # 더미 콘텐츠로 빌드 검증


```





| 옵션 | 설명 |


|---|---|


| `-o` 생략 | `<회의명>_회의록_<YYYYMMDD>_<작성자>.hwpx` 로 **입력 파일과 같은 폴더**에 저장. 날짜는 `일시` 에서 추출 |


| `--pdf` | 한글 COM 으로 PDF 도 생성(검증용) |


| `--open` | 만든 hwpx 를 한글로 열기 |


| `--images-dir` | 그림 상대경로 기준 폴더(기본: 입력 파일 폴더) |


| `--no-defaults` | `defaults.json` 무시 |





`defaults.json`(스킬 루트)에 적어 둔 **작성자·관리자·장소·상시 참석자**는 개요에서 비워 둔


칸에만 자동으로 채워진다. 매번 같은 값을 다시 적지 않아도 된다.





출력 JSON 의 `PASS: true` 와 `empty_fields`(자료에서 확인되지 않아 빈 칸)를 확인한다.





참고 입력: `examples/sample_outline.txt`(개요), `examples/sample_input.json`(JSON).


두 파일 모두 실제 회의록 1건을 그대로 옮긴 것이다.





## 텍스트 개요 형식





완성된 회의록 모양 그대로 적으면 된다. `#` 으로 시작하는 줄은 무시된다.





```


제목: 통합 예약시스템 도입 검토를 위한 간담회


일시: 2026년 9월 11일 14시


참석자: (○○본부) 팀장 김철수


참석자: 주무관 최지훈, 임재현, …





1. 회의 목적


◦ 부서별 운영 현황을 공유하고 추진방향 논의





2. 주요 논의 사항


가. 운영 현황


◦ (사업명) 통합 예약시스템 구축 용역


  - 승인 절차 구분


    ○ 자동 확정 자원과 승인 필요 자원을 자원 등록 시점에 구분


※ 공동장비는 2차년도로 분리 추진





[표] 자원 보유 및 예약 창구 현황


구분 | 주요 업무 | 보유 수량


교육시설 | 강의실 · 실습실 | 0,000개


=합계 | 000실 | 0,000개


[끝]





[그림] 화면1.png | 화면2.png


[캡션] 예약 화면 | 승인 화면


```





- 절 표제 `1.` / 소제목 `가.` / 대주제 `□` / 글머리 `◦` `-` `○` / 단서 `※` — 적은 그대로 매핑.


- 기호 없이 들여쓰기만 해도 깊이를 판단한다(3칸 이상 `-`, 6칸 이상 `○`).


- 표: 첫 줄이 머리행, `|` 로 칸 구분. **열 폭과 정렬은 내용 길이에 맞춰 자동 조정.**


  행 앞의 `=` → 합계행(음영+굵게), 칸의 `^` → 위 칸과 세로 병합.


- 그림: 한 줄에 1~2장. `[캡션]` 은 바로 앞 `[그림]` 에 붙는다.





## 콘텐츠 JSON





```json


{


  "meta": { "output": "결과.hwpx" },


  "title": "통합 예약시스템 도입 검토를 위한 간담회",


  "datetime": "2026년 9월 11일 14시",


  "author": "홍길동",


  "location": "○○본부 ○○○호",


  "manager": "김철수",


  "attendees": ["(○○본부) 팀장 김철수", "주무관 최지훈, 임재현, …"],


  "sections": [


    { "heading": "회의 목적",


      "blocks": [ { "type": "bullet", "text": "…" } ] },


    { "heading": "주요 논의 사항",


      "topic": "대주제",


      "blocks": [


        { "type": "subheading", "text": "운영 현황" },


        { "type": "bullet",    "label": "사업명", "text": "…" },


        { "type": "subbullet", "text": "…" },


        { "type": "subsub",    "text": "…" },


        { "type": "note",      "text": "…" },


        { "type": "table", "headers": ["구분","주요 업무"], "widths": [9,28],


          "align": ["center","left"],


          "rows": [["교육시설","…"], ["^","…"]],


          "total_row": true, "caption": "표 제목" },


        { "type": "image", "files": ["a.png","b.png"],


          "captions": ["교육 계획","유지보수 계획"], "max_height": 22000 },


        { "type": "spacer" }


      ] }


  ]


}


```





- 절 번호(`1.` `2.` …)와 소제목 문자(`가.` `나.` …)는 **자동 부여**. 강제하려면 `number`, `marker`.


- 표 `rows` 의 `"^"` = 위 셀과 세로 병합. `widths`·`align` 을 생략하면 내용에 맞춰 자동 계산.


- 본문 어디서나 `**굵게**`. `text` 맨 앞의 `(라벨)` 은 자동으로 굵게 처리되므로


  `{"type":"bullet","text":"(사업명) …"}` 와 `{"label":"사업명","text":"…"}` 는 같은 결과.


- `max_height` 는 그림 한 장의 최대 높이(HWPUNIT, 7200 = 1인치). 생략하면 폭 기준으로만 맞춘다.





## 동작 방식





`assets/template.hwpx` 는 원본 양식에서 캡처 이미지와 본문만 비운 빈 회의록이다.


`scripts/build_minutes.py` 는


- `Contents/header.xml` 에 본문용 자원만 **추가**(borderFill 17, charPr 33~40, paraPr 41~50)


- `Contents/section0.xml` 의 제목표 값 셀 6개와 본문 셀(r7c0)만 교체


- 그림은 `BinData/` 에 넣고 `Contents/content.hpf` 에 등록





하므로 secPr(용지·여백·쪽번호)·글꼴·테두리·표제 박스는 원본과 완전히 동일하다.





## 주의





- **LibreOffice 는 HWPX 를 못 읽는다.** 확인은 한컴오피스 한글(또는 `scripts/hwp2pdf.py`)로 한다.


- 그림의 렌더 크기는 `hp:imgRect × (curSz / orgSz)` 로 결정된다. `imgRect` 는 **원본 크기**,


  `curSz`/`hp:sz` 는 **표시 크기**로 두어야 한다. (imgRect 를 표시 크기로 바꾸면 이중 축소된다.)


- 회의 중 발언을 그대로 옮기지 않는다. 논의 결과를 행정문서 개조식으로 정리한다.
