# 회의록 본문 작성 지침



기존 회의록 4건(통합 예약시스템 추진방향 / ○○대 사례 검토 / 2단계 고도화 /

○○ 사업 계획)에서 추출한 작성 규칙. **이 문서를 본문 설계 전에 읽는다.**



## 1. 절 구성 패턴



회의 성격에 따라 아래 셋 중 하나를 고른다. 절은 보통 3~6개.



### (A) 논의형 간담회 — 가장 흔함

```

1. 회의 목적          ← ◦ 1개. "…에 앞서 …을 검토하여 … 논의"

2. 주요 논의 사항      ← 가./나./다. 로 갈라서 서술

3. 검토 필요사항       ← 결론이 안 난 항목

4. 추후 일정          ← 다음 액션

```



### (B) 현황 → 문제 → 전략형

```

1. 회의 내용    2. ○○ 현황(표)    3. 문제점(◦ (라벨))    4. 추진 전략 및 실행 방안

```



### (C) 보고회형

```

1. 회의 개요   2. 사업 개요   3. 주요 과업 추진 결과(표)

4. 주요 고도화 서비스   5. 운영지원 계획   6. 논의사항 및 향후 계획

```

필요하면 절 위에 `□ 대주제` 한 줄(`"topic"`)을 둔다.



## 2. 글머리 위계



```

1. 절 표제                (14pt 굵게)

 가. 소제목                (13pt 굵게)   ← 절 안이 2개 이상 갈래일 때만

 ◦ (라벨) 본문             (12pt)        ← 주 서술 단위

   - 하위 본문             (12pt)

     ○ 세부 본문           (12pt)

   ※ 단서·보충             (10pt)

```

- `◦` 는 **한 항목 = 한 문장**. 두 문장이 필요하면 항목을 쪼갠다.

- `-` 는 `◦` 를 항목별로 나열할 때만. `○` 는 `-` 를 더 쪼갤 때만(3단 이상 잘 안 씀).

- `※` 는 수치 근거·예외·후속 이관 사항.



## 3. 문체



- **개조식·명사종결**: "…필요", "…논의", "…확정", "…제시 요구", "…확보 필요", "…확인".

  `-습니다/-했다` 금지. 서술어를 명사로 끝낸다.

- **(라벨) 선행**: 항목 성격을 2~6자 라벨로 앞세운다.

  `◦ (사업명) …` `◦ (추진경과) …` `◦ (통합 관리 체계 부재) …` `◦ (오픈 준비) …`

  개요·목록성 항목은 `(대학명) (사업명) (용 역 비) (수행업체) (추진경과) (주요내용)` 순.

- **발언 인용 금지**: "누가 무엇을 말했다"가 아니라 **논의 결과**를 쓴다.

  참석자 개인 이름은 본문에 넣지 않는다.

- **정량 근거 우선**: 자료에 수치가 있으면 반드시 본문 또는 `※` 에 옮긴다.

  `영문약어 중복 00.0%`, `테이블 0,000개`, `○○,○○○,○○○원`, `약 4개월`.

- **날짜·기간 표기**: `2026. 5. 6. ~ 2026. 8. 31.(약 4개월)`,

  `착수(’25. 10.) → 중간보고(’25. 11. 25.) → 완료보고(’25. 12.)`. 연도 생략은 `’25.`.

- **가운뎃점**: 나열은 `교육·연구·행정`, `표준화·메타데이터`. 슬래시는 최소화.

- **번호 원문자**: 자료가 ①②③ 로 목록화돼 있으면 그대로 살린다.

- **낫표**: 사업명·규정명은 `「○○ 사업」`.



## 4. 표를 쓸 때



- 현황·비교·결과 요약처럼 **2차원 데이터**일 때만. 서술로 되는 건 표로 만들지 않는다.

- 첫 열은 `구분`/분류명(가운데 정렬), 나머지는 내용(왼쪽) 또는 수치(가운데).

- 같은 분류가 연속되면 `"^"` 로 세로 병합한다.

- 합계행은 `"total_row": true`.

- 표 바로 앞 `◦`/`-` 항목에 "…현황은 다음과 같음" 같은 유도 문장을 둔다.

- 표 아래 근거·기준은 `※` 로.



## 5. 그림을 쓸 때



- 개념도·화면 캡처를 `"image"` 블록으로. 한 줄에 1~2장, 각 장에 `[캡션]`.

- 캡션은 `[예약 화면]`, `[성과관리시스템 품질 향상 개념도]` 처럼 대괄호 명사구.

- 캡처가 많으면 2장씩 여러 블록으로 나눈다. 3장 이상 한 줄은 판독이 어렵다.



## 6. 제목표



| 칸 | 작성 규칙 |

|---|---|

| 제 목 | 회의 명칭. `…를 위한 간담회`, `… 논의`, `… 완료보고회` |

| 일 시 | `2026년 9월 11일 14시` (시각 모르면 날짜까지) |

| 작성자 | 회의록 작성 담당자 |

| 장 소 | `○○관 ○○○호`, `○○본부 ○○○호` |

| 관리자 | 소관 팀장 |

| 참석자 | `(부서) 팀장 …, …` 다음 줄에 `주무관 …` 나열. 외부는 `(○○○) 사업 수행팀` 처럼 괄호로 소속 구분. 인원이 많으면 `… 외` 로 줄여도 된다 |



참석자는 줄 단위 배열로 넘긴다. 한 줄 40자 내외에서 끊는다.



## 7. 분량



- 2~3쪽이 표준. 1쪽은 논의가 빈약해 보이고 4쪽 이상은 회의록 범위를 넘는다.

- `◦` 항목은 절당 2~7개.

- 자료에 없는 내용을 추론해 채우지 않는다. 확인이 필요한 건 `검토 필요사항` 절에

  "…별도 확인 필요" 로 남긴다.
